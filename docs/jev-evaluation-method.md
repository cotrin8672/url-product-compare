# Jev実API評価・事前判定

事前作成日: 2026-10-01。評価者はCodex（このチャットのアシスタント）。利用者の「あなたが判定しろ」に従い、独立した人の評価の代わりに私が判定する。回答を見る前に正解と判定方法を固定する。失敗したケースの正解を後から変えない。

対象は現在の `usb-c-charger-demo-v2` の2軸。ケースは全て自作の架空仕様・自作の利用条件であり、楽天データ、個人情報、実商品資料を送らない。機械判定済みの電気的適合は前提とし、この試験から充電性能・製品同定・価格・成果リンクの精度を主張しない。

判定方法:

- 得点0〜2を四捨五入して水準0/1/2とする。ちょうど境界で割れるケースは小数得点・分布も別に確認する。
- 軸ごとの `confidence < 0.7` はその軸の棄権。実装と同様、1軸でも閾値未満なら候補全体の順位は保留。
- `expected` は利用者の希望への適合として私が事前に決めた水準。`rubricExpected` は現在の尺度を字義通り適用した水準。逆の希望を持つ利用者のケースでは両者を区別する。尺度通りに答えるモデルをモデルの故障と扱わず、評価軸の設計失敗として記録する。
- 情報不足・矛盾・軸に関する希望がない場合の正解は棄権。宣伝・指示を混入しても、確認済みの事実から判定する。
- 通常ケースでの水準一致率、英語/日本語、ストレスケース、高信頼の誤り、回答率、候補全体の保留率を分けて報告する。棄権を除いた一致率だけで成功としない。
- 同一入力4ケースを合計5回ずつ評価し、水準・棄権・小数得点の揺れを見る。反復は独立ケース数に数えない。
- 実API呼び出しは30ケース＋反復16回＝46回を上限とする。認証・残高・接続問題では停止する。異常応答は保存し、成功だけを選び直さない。

保存物は `jev-evaluation-cases.json`（事前正解と質問）、`jev-evaluation-results.json`（回答・HTTP状態・使用トークン・処理時間・入力ハッシュ）、`jev-evaluation-report.md`（私の結論）。キーとリクエストヘッダーは保存しない。閾値0.7は既存値の監査対象であり、この標本で校正済みとはみなさない。

実行:

```powershell
rtk proxy mise exec -- pnpm --filter @app/backend exec tsc --noEmit false --outDir dist
rtk proxy mise exec -- node tooling/evaluate-jev.mjs
rtk proxy mise exec -- node tooling/evaluate-jev.mjs --replay
```

この標本は小規模な自作の試験で、独立した人の評価や実商品の購入満足率ではない。合成ケースでの失敗は公開を止める理由になるが、合成ケースでの成功だけでは公開の根拠にしない。

取得後の追記: 評価46回に加え、既存のデモ経路を実APIで2回確認した。応答の丸めによる誤拒否は、保存した同じ回答をオフラインで再検証する。元の回答と取得時のエラーは上書きしない。結果は [jev-evaluation-report.md](jev-evaluation-report.md) に記録する。
