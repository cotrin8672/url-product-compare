# カテゴリ・評価軸・ショップの追加

定義源は `packages/backend/src/comparison/consumer-catalog.ts` です。`publicConsumerCatalog()` をAPIが `GET /api/catalog` で配信し、クライアントが検証します。静的生成器だけがコンパイル済みの公開カタログを読み、Webはbackendを直接参照しません。

## カテゴリと評価軸

1. `consumerCatalogCategories` に `ConsumerCategoryDefinition` を追加します。IDは小文字で始まる英数字・アンダースコア・ハイフンです。重複とパス文字を拒否します。
2. `fields` に内部で確認する項目、`axes` に数値の評価軸を指定します。価格以外の軸は実在する数値項目IDを参照し、`label / lowerIsBetter / weight` を持ちます。重みは正の有限値です。
3. `providerBindings` にショップごとのジャンルコードと検索用 `keyword`、必要なら `searchExcludeKeyword` を指定します。コードは数字に限定せず、カテゴリ一致と祖先解決はアダプタが担当します。
4. 判定、曖昧さ、新品・同定・リンク検証、数値の方向と重みをテストし、`rtk mise run verify` と公開ページ生成を実行します。

画面はURL入力だけで、条件は `{}` です。比較表は総合、税込価格、評価の内訳、購入ボタンの順です。価格以外の数値評価軸は内訳だけに表示し、個別行に重複させません。点数は既存の比較ロジックが返す0〜100点を使い、未確認は「—」です。新しいCPU名・文字項目・機能フラグから点数を作りません。`mainFields` と条件定義は内部APIや互換経路のメタデータとして保持します。

`ConsumerFieldDefinition` の型・上下限・抽出規則は値の検証に使います。`filter / presets` は内部APIの条件メタデータで、画面の入力項目ではありません。新しい抽出値には掲載URLを指す引用と出典が必要です。不明は `null`、矛盾は `conflicts` に記録します。相対スコアには確認済みの正の数値が必要です。

## ショップ

実アダプタは楽天市場のみです。候補検索は入力URLに対応するショップで行い、複数ショップの同時集約はありません。

1. `providers/{provider}/` に `ConsumerProvider` を実装し、ID・表示名・商品ホスト・広告ホストを定義します。同じIDや複数プロバイダに一致するURLは拒否します。
2. URL受付、掲載取得、ジャンルと祖先、カテゴリ一致、検索・補完、引用付き情報、許諾を実装します。HTTPと認証の詳細はアダプタ内に置きます。
3. 共通の `ConsumerListing` を返します。同定は `identityVerified`、任意の共通コードは `gtin` です。楽天製品IDを共通型の必須項目にしません。
4. 状態は `new / used / refurbished / unknown`。中古・再生品と不正な成果リンクは採用しません。`allowUnknownCondition` を設定したカテゴリでは状態の記載がない掲載も比較し、画面に「商品状態：未確認」と表示します。既定の6カテゴリはこの設定を使い、状態不明を新品に書き換えません。
5. `permissions()` に取得・表示・広告・AI・保存の許諾と保存期限を返します。永続ジョブは明示的な保存許諾を必要とします。
6. bootstrapの共有構築で登録し、HTTPとワーカーを同じ構成にします。カテゴリの `providerBindings` も追加します。
7. そのショップのURL、広告形式、画像、ジャンルコード、引用出典を使うbackendとクライアントのテストを追加します。

クライアントは公開HTTPS・登録ホスト・広告の明示的な遷移先を検証します。楽天固有の広告パス・パラメータ・画像ホストは楽天用の厳密検証を維持します。引用は画面に展開せず、API応答とクライアント検証に保持します。

## 公開APIとジョブ

ブラウザは公開ゲートウェイの catalog・detect・開始・読取を使い、Bearerを入力・保存しません。高コストPOSTはIPごとに1分6回、インスタンス単位で制限します。内部の取消APIと既存診断は保護を維持します。

操作ごとのIDとアクセスキーを生成し、通信再送では同じ組を使います。ジョブID・キー・期限・revisionとカテゴリIDだけをsessionStorageに保持し、再読み込みで進捗や結果をAPIから復元します。期限が切れたら表と商品リンクを取り除きます。

検証例は API クライアントの `index.test.ts` とbackendの `consumer-foundation.test.ts / consumer-jobs.test.ts` です。依存・設定・生成規則の変更は人間のレビュー対象です。
