# 商品サイトの提携準備：実装と引き継ぎ

対象は `apps/products`。商品サイトのAmazon・Yahoo!ショッピング提携準備を先行し、ハブサイトと他カテゴリサイトの改修は含めない。

## 実装した内容

- トップに対応ショップ、利用手順、カテゴリ別ガイド、FAQを追加。
- 比較アプリと説明記事を分離。カテゴリ説明や比較方法がJavaScript起動後に消える構成を解消。
- 6カテゴリの選び方、メモリと保存容量、価格の読み方、スコアの読み方、購入前チェックの計10記事を追加。
- 記事に要点、目次、公開・更新日、確認項目、関連情報、比較ツールへの導線を設置。
- 実機レビューや専門家監修を装わず、説明用の架空例は明記。
- 比較方法、編集・広告方針、プライバシーと外部サービス、利用上の注意、このサイトについての常設ページを整備。
- 広告表示を折りたたみの外に表示し、報酬と順位の関係を説明。
- 比較結果に楽天市場が情報元であることと、商品ごとの確認日時（日本時間）を表示。
- 記事と常設ページをサイトマップに追加。既存のプレビューnoindex・canonicalの方針を維持。
- 依存関係・Lint設定・生成ルールの変更はなし。静的ビルド検査は、既存ルートの検査を維持し、新規15ページのタイトル・見出し・サイトマップの検査を追加した。tooling/build-site.mjs の変更は人によるレビュー対象。

## 委託先から受け取るもの

`apps/products/src/content/publisher.ts` に、承認された公開名と実在する問い合わせ先を入力する。メールの場合は `mailto:`、フォームの場合はHTTPSのURLを指定する。未入力時は該当表示を出さない。架空の名前、送信できないフォーム、ダミーのメールは使用しない。

この情報が未提供の現状では、運営者情報と問い合わせ窓口の整備は完了していない。記事数だけを理由に申請準備完了や審査合格を保証しない。

申請前に委託先へ確認する項目：

1. 公開する運営名と、実際に対応できる問い合わせ窓口。
2. 広告アカウント・商品データ利用の名義と利用権限。
3. 個人情報の問い合わせ対応、保存期間・削除手順など、実運用と公開方針の一致。
4. 新規記事の内容・出典の確認と、今後の更新担当。
5. 申請先に登録する実URL、公開範囲、広告主ごとの条件。

Amazon・Yahoo!への申し込み、契約の承諾、未取得のアフィリエイトIDの追加は実施していない。

- 各ガイド内にメーカーの公式資料を掲載。文章やデザインの転載ではなく、構成の参考と事実確認に利用。

## ローカルでの確認

通常の開発は mise 経由で `pnpm --filter @app/products dev` を実行する。

作業環境内のGit管理外の検証用として、実APIを用いる表示確認用に `output/affiliate-preview-20261031.mjs` を用意。ビルド済みの `apps/products/dist` を127.0.0.1:4322で配信し、比較リクエストだけ既存APIへ中継する。公開設定やAPIの許可Originは変更しない。実行は `rtk proxy mise exec -- node output/affiliate-preview-20261031.mjs`。これはローカルQA用で、本番への配布対象ではない。

受け入れ確認は `rtk proxy mise run verify`。Cloudflare向け静的ビルドは既存の `build:pages` を使用する。
