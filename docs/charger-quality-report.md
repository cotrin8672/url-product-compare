対応公式URLを厳密に確認し、毎回取得したJSON-LDのメーカー・型番、選択JAN、仕様表を照合する。出力表・重量・色などのレビュー済み仕様表のSHA-256が変わったら再レビューまで停止し、過去の取得結果に戻さない。

総W数だけで判定せず、接続台数ごとのポート配分、PD電圧・電流、PPS範囲・電流、ポート上限、総出力、ケーブル能力を検査する。接続順を変えても割り当てを探索できる。適合時は端末ごとの接続先を表示する。「指定モードで供給できない」と「一切充電できない」は区別する。

本体刻印は仕様表のC1/C2という記述から推測しない。希望／必須条件の未確認は保留にする。重量・外形体積は公称概数で並べ替えられる。取得ページ全文の保存、AIへの送信、販売価格・在庫の生成は行わない。

## Jevと実用範囲

以前の [Jev実API評価](jev-evaluation-report.md) では高確信の誤答があった。確信度を製品判定の正確さとして扱わない。電気的適合・プラグ形状・公称値はコードで評価し、現行の公式比較ではJevを使用しない。

文章でしか評価できない軸を導入する場合は、出典・使用許可、軸ごとの事前ラベル、未見商品の誤適合率・保留率・順位安定性を別に検証する。未確認事実をJevで補完しない。

利用者の入力は特定の必要動作点として扱う。端末の全受入モードや実測速度・発熱・長期信頼性は未評価。メーカーの接続追加・抜去時の一時中断も画面に示す。未対応型番や販売店掲載の同定・価格・在庫統合を、現行3型番と同じ品質として扱わない。

## 起動・再評価

このWindows環境では既存のFirebase梱包で依存関係を解決して起動できる。公式比較はAI・楽天の設定なしで利用できる。

```powershell
rtk proxy mise run firebase:package
rtk proxy mise exec -- node apps/api/dist/firebase/apps/api/src/local.js
```

別ターミナルでWebを起動し、公式URL取得→端末とケーブル能力入力→確認→比較を行う。

```powershell
rtk proxy mise exec -- pnpm --filter @app/web dev --host 127.0.0.1
```

再評価はビルド済みモジュールを使う。現在は比較対象4型番の公式ページを取得し、従来3型番の96判定を検証する。AI課金なし。

```powershell
rtk proxy mise exec -- pnpm test
rtk proxy mise exec -- node tooling/evaluate-chargers.mjs
rtk proxy mise exec -- pnpm exec oxfmt --write docs/charger-quality-results.json
rtk proxy mise run verify
```
