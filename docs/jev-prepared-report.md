# Jev判定の改善実装と実API検証 — 2026-10-02

## 実装したこと

共有のrankProductsを変更し、rankChargers・bootstrap・メーカー取得処理・検証CLIへ接続した。新しい依存や設定例外は追加していない。

- 事実はconfirmed / unknown / conflictingを区別する。確認済み事実には値と根拠記述を必須にし、未確認・矛盾する事実に値を置けないスキーマにした。必要な未確認情報は、採点前に止まる。「Not verified」だけを値として渡す旧形式は受け付けない。
- 希望は評価軸ごとにconfirmed / not_applicable / needs_confirmationを検証する。未確定の解釈はconditions_need_confirmation、全軸不要はno_assessment_requested。不要な軸の質問・事実・重みを除く。
- 1候補・1軸ごとに、その軸の希望、必要な事実、根拠記述だけを送る。全軸の事実を同じstateへ混ぜない。2軸・2候補では4回のAPI呼び出しになるため、従来の1候補1回より呼び出し数が増える。
- 充電器デモの尺度を「特定の形状や表示を無条件に優遇」から「明示された希望へ適合」に変更した。部分適合は、利用者が明示的に許容した回避策の場合に限る。版はusb-c-charger-demo-v3。
- ELECOMの折り畳み事実には、検証済み仕様表のコンセントプラグ仕様の記述を保持する。メーカー情報のAI利用権限は従来どおりdeniedで、Jevへの送信許諾を勝手に変更していない。
- 必須条件の既知の不適合を先に除外し、残った候補の不足を確認する処理、権限・失効・SKU一致、分布・尺度の応答検証、同順位、公開％の停止は維持した。

確認状態の宣言と出典記述の存在だけで、意味上の正しさが保証されるわけではない。入力事実の正しさは取得処理・資料レビューで確認する責務が残る。曖昧さを自動検出する汎用AIや、未登録カテゴリの自動実比較を実装した変更ではない。

### 未使用モデルの根拠と範囲

[象印のSM-TA公式ページ](https://www.zojirushi.co.jp/syohin/bottle/smta/)でSM-TA48、スライドロック後のボタン開閉、別売のスクリューせんへの交換を確認した。CLIでも同ページを取得し、レビュー対象の記述が存在するか確認した。

Jevへ送ったのは私が作成した短い事実要約で、メーカー文章全文ではない。交換可能と標準付属を区別し、別売購入を許容する条件は適合、両方の標準付属を希望する条件は不適合と判定した。参照したページでは全パーツ食洗機対応や操作力の数値を確認できないため、それを要求する条件は採点前に保留した。

これは未使用の別メーカーの1モデルに対する資料付き条件試験で、JAN・販売店SKU・在庫・価格の照合、自動取得アダプタの追加、実機操作の検証は含まない。3実モデルの比較と架空プラグの回帰を、市場全体の推薦精度へ一般化しない。

## 通常のbootstrap経路で見つかった追加問題

最初の実API確認では、デモの「端子を保護したい」という条件と「プラグが本体へ折り畳める」という記述の対応が低信頼となり、assessment_uncertainで総合順位を保留した。診断用に同じ条件の4応答を取得し、折り畳み候補のプラグ評価がscore 1.79 / confidence 0.68であることを確認した。

形状から保護性能まで推測させず、デモ条件を「折り畳み方式を明示的に希望する。物理的な損傷防止は評価しない」へ限定した。実利用者の希望を勝手にこう変換する処理は追加していない。

変更後のbootstrap経路は実APIで通過し、65W候補を電気的必須条件で除外、85Wを1位、100Wを2位とした。条件を変更した別試験であり、元の目的について判定できるようになった証拠ではない。元の失敗と診断を保存し、成功するまで同じ入力を再試行して選別していない。

- [保留の診断と4応答](jev-demo-prepared-diagnostic.json)
- [条件を明示した経路の4応答](jev-demo-prepared-confirmed-live.json)

## 検証と残る範囲

共有処理の回帰テストに、不要軸・未確認・矛盾・曖昧条件の呼び出し停止、希望と事実の軸別分離、根拠記述の保持を追加した。既存の必須条件・権限・失効・分布検証・同順位のテストを維持した。水筒の必須条件は再実行で34/34一致。

`mise run verify`は整形・ESLint・全workspace型検査・Knip・guardrail・全テストを通過した。backendは35/35、API clientは4/4。保存応答のオフライン再検証は水筒21/21条件・プラグ10/10条件が一致した。メーカー取得処理の再確認では、充電器96/96判定と9/9防御検査、追加型番26/26判定が一致した。これらの再確認ではJev実APIを追加で呼んでいない。

`mise run firebase:package`も成功し、生成パッケージのHTTP経路・Firestoreアクセス制約・TTL・保存失敗の検査を通過した。pnpmの既存のlegacy deploy・非推奨間接依存・bin生成・ビルドスクリプト未実行の警告は残る。デプロイ先での動作確認はこの検証に含まない。

今回の限定した誤判定と送信経路は改善したが、用途一般の推薦順位・適合度％の校正は未完了。閾値0.7を公開品質の保証にはしていない。Score以外の質問型は、今回の修正に必須ではなかったため本番adapterへ追加していない。

Webの公式商品フローは確認済み充電器の仕様比較で、Jevを使う実商品の推薦フローはまだ接続されていない。任意URLからの製品同定・別モデル探索・資料取得・ユーザーの解釈確認・Jev推薦を通す残作業と、この判定処理の修正を区別する。
