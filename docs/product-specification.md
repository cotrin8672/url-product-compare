# 家電・PC比較サービスの仕様

更新: 2026-10-08。

利用者は商品URLを入力して比較します。カテゴリは自動判定し、複数候補がある場合だけ選択ボタンを表示します。条件・補助語・トークンの入力、並び順の選択、取消ボタン、出典の展開はありません。比較入力の `conditions` は `{}`、`keyword` は `null` です。比較モードは公開URLに従い、通常はおすすめ順です。

入力商品と最大5候補を画像付きの表で表示します。青いURL入力パネル、商品画像と店舗名、総合評価、税込価格、評価の内訳、購入ボタンの順に配置します。価格は円の行だけ、価格以外の評価軸は内訳だけに表示し、同じ項目を別行に重複させません。総合と内訳は0〜100点です。未確認の点数は「—」とし、仕様の生値やCPU・文字情報を点数に置き換えません。商品URLの変更で旧結果とリンクを消します。

評価軸はカタログの順番で先頭6項目までを常時表示します。残りの軸と文字・真偽値の仕様は、表の下の「詳細項目を表示」で全商品まとめて開閉します。CPU・GPU型番、OS、通信規格は仕様の行として表示し、性能点に変換しません。項目の順番は全商品で固定し、欠損でも行を詰めません。表示の開閉はAPIの総合点や順位を変更しません。

## カテゴリと評価

定義源は backend のカタログです。全カテゴリで価格と総合を表示し、次の数値評価軸を追加します。

| カテゴリ       | 価格以外の評価軸                                                     | 楽天ジャンル |
| -------------- | -------------------------------------------------------------------- | ------------ |
| ノートPC       | メモリ・保存容量・軽さ・バッテリー時間・解像度・更新回数             | 100040       |
| デスクトップPC | メモリ・保存容量・GPUメモリ・CPUコア数・USB-Aポート数・USB-Cポート数 | 211368       |
| タブレット     | メモリ・保存容量・軽さ                                               | 560029       |
| スマートフォン | メモリ・保存容量・軽さ                                               | 560202       |
| テレビ         | 画面サイズ・解像度・更新回数                                         | 563843       |
| モニター       | 画面サイズ・解像度・更新回数                                         | 110105       |

PCの追加評価にはCPUスレッド数、GPUメモリ、USBポート数、画面の明るさ、バッテリー容量、本体寸法など、カテゴリに登録した数値項目を使います。コア数・スレッド数・GPUメモリは数量の比較であり、CPU/GPU全体の性能やゲーム性能の指標ではありません。サイズ・重さ・厚さは小さい方、容量・時間・コア数・端子数などは大きい方を100点の基準にします。仕様は楽天APIのラベル付き記載から取得するため、記載のない項目は未確認です。

点数は項目ごとに確認済みの数値がある適合商品2件以上で相対比較します。端子数などカタログで0を許可した項目は、明記された0も採点します。小さい方を優先する軸は `最小値 / 商品の値 × 100`、大きい方を優先する軸は `商品の値 / 最大値 × 100` を丸めます。0が最良値の場合は0同士を100点とし、大きい方を優先する軸で他商品が正の値なら0点です。JAN未同定でも掲載に明記された仕様は採点し、欠損や他商品の保留で既知の点数を消しません。総合は適合商品すべてで確認できる共通評価軸の重み付き平均で、価格以外の共通軸が必要です。既存6カテゴリの重みは均等です。価格幅や欠損で全評価軸が揃わない場合も、適合商品が2件以上あり共通軸で総合点が出れば、その点数でおすすめ順位を付け、順位とメダルを表示します。必須条件の確認待ちや共通項目不足では順位を保留します。同点は同順位です。価格順位は正の単一税込価格で、同額は同順位です。送料・ポイント・クーポンは順位に含めません。

## 内部の取得と検証

実API接続は現在楽天市場のみです。URL完全一致の入力掲載を取得し、新品の明示、ジャンルと祖先、成果リンク、取得・表示権限を検証します。製品同定はJANによる重複整理と製品APIの仕様を採用するための検証に使います。候補は6掲載ずつ最大3ページ探索し、掲載ID・URL・確認済みJANの重複を除きます。おすすめ比較では入力商品の既知の数値仕様が揃う候補を優先し、最大5候補、検索末尾、上限、取得エラーで探索を終えます。

仕様・引用・出典・矛盾は内部データとAPI応答に保持し、APIクライアントでも値と点数、順位、リンク、期限を検証します。画面に引用欄はありません。明示されたラベルと単位をコードで抽出し、容量の割り当てが曖昧な場合だけ任意設定のJev Choiceを最大1回使います。Jevは実際の引用を選ぶだけで、数値計算や仕様生成は行いません。メイン経路のOpenAI呼び出しは0回です。

## APIと保存

ブラウザは公開ゲートウェイの catalog・detect・ジョブ開始・読取だけを使います。Bearerトークンはサーバー側に保持し、入力欄や公開JavaScriptに含めません。高コストなPOSTはクライアントIPごとに1分6回、インスタンス単位で制限します。これは全インスタンス共通の利用者別制限ではありません。

ジョブには操作ごとのランダムなIDとアクセスキーを使い、同じ開始操作の再送は同じジョブになります。ブラウザはジョブID・キー・期限・revisionとカテゴリIDだけをsessionStorageに保持し、結果はAPIから復元します。保護された取消APIと既存の診断APIは保持し、取消と完了の競合では先に確定した終端状態を維持します。

永続保存はプロバイダの保存許諾がある場合だけです。結果の期限は最大15分と掲載・許諾期限の最小値、メタデータは最大60分です。期限切れではAPIからの取得を拒否し、画面の表と商品リンクを取り除きます。Firestore TTLは物理削除に使います。

公開HTMLはトップ・カテゴリ・比較モードと既存の比較方針URLを生成します。JavaScript無効時には短い見出しとリンクを表示し、有効時はURL入力の画面に切り替えます。本番オリジンにcanonicalとsitemapを付け、一時ジョブ・結果・クエリは検索公開しません。実商品での充足率、抽出精度、広告成果、費用は未測定です。
