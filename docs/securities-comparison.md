# 証券口座サービス比較（初期実装）

2026-10-25。`/securities/` に専用画面、`GET /api/securities` に初期比較、
`POST /api/securities` に条件付き試算を追加した。Astroの静的ページとAPIクライアントを使う。
既存の商品比較・ふるさと納税の比較ロジックや、一時ジョブの期限は変更していない。SEOは保留し、
この新ページはnoindex。新しい依存、AWSリソース、デプロイは追加していない。

## 対応する比較

- 国内現物・単元株：NISA成長投資枠／課税口座、同額で約定する注文の売買手数料合計。
  SBIはインターネットコースと所定の電子交付設定、楽天の課税口座はゼロコースとSOR同意、
  マネックスの課税口座は取引毎手数料コース。未達条件や他のコースは0円とせず保留する。
  全社の試算条件が揃う場合だけ順位を表示し、未確認の会社がある場合は全体順位を保留する。
- 積立：各社指定の代表カードを利用する場合の通常ポイント。SBIは三井住友カード（NL）の
  入会2年目以降、楽天は一般カード、マネックスはマネックスカード。積立額はカード決済額。
  対象ファンド・本人名義カード・必要な口座設定を満たす場合の参考値。
- 積立は端数調整前の参考ポイント。プログラム間の円換算・順位は付けない。
  年会費、キャンペーン、Olive上乗せ、保有残高ポイント、投資商品の収益は算入しない。
  信託報酬等の保有コストを売買手数料無料と混同しない。

計算は純粋なTypeScriptの比較ロジック。Jev・外部API・ユーザーの金融口座には接続しない。
値は公式資料を確認したコード上のスナップショットで、ASPの実API応答とは表示・説明を区別する。

## 入力・表示

商品・ふるさと納税・証券会社のヘッダーは共通。証券画面は条件入力、3社比較表、
折りたたみ式の内訳・出典という配置を維持する。

- 年間・月間カード利用額の空欄と明示的な0円を区別する。空欄の会社は試算・内訳を表示せず、
  「条件未確認」とする。API互換の0円を送る場合も、欠落項目の情報をリクエストに紐づけ、
  その0円による計算を利用者の結果として見せない。
- 編集中の条件と応答に紐づく条件を照合し、違う場合は「変更が未反映」「前回の結果」を表示する。
  金額だけでなく口座種別、付与区分、無料条件、空欄と0円の違いも判定する。
- 送信時は折りたたみ状態に関係なく全入力を検証する。不正値は送信せず、項目別の説明を出し、
  必要な入力欄を開いてフォーカスする。「条件を設定」も会社ごとの該当欄へ移動する。
- モバイルの主要な補足・リンクは12px。長い金額は数字を途中で改行せず、文字サイズと単位の
  別行表示で収める。公式リンクの背景は小さい白文字を読み取れる暗さにする。
- 公式条件の確認日は常時表示する。期限切れ・更新待ちの会社は数値を隠し、
  運営による更新が必要であり、入力変更では解消しないことを案内する。

## 根拠・更新

初期値は `providers/securities/catalog.ts`。各社の出典URL、確認日時、次回確認予定を持つ。
初期の次回確認は24時間後。予定を過ぎても会社・出典・参考説明は残し、試算と順位だけ保留。
自動巡回・Jevによる変更抽出・DynamoDBへの承認済み改訂保存は今回未実装。

## ASP連携の範囲

両ASPの商品APIが対象証券案件に対応するかは未確認。VCの商品取得SDKを証券条件APIと
みなしたり、ATの未確認エンドポイントを呼んだりしない。レポートAPIを条件取得に使わない。
初期状態のリンクは公式サイトで、架空の広告リンクを表示しない。

提携・掲載確認済みのリンクを設定できる。ローカルはサーバー専用環境変数
`SECURITIES_AFFILIATES`、LambdaはAPI_CONFIGURATIONの `securitiesAffiliates` 配列。
各要素は `brokerId`、`provider`、`programId`、`url`、`approvedUntil` の5項目。
brokerIdはsbi/rakuten/monex、providerはvaluecommerce/accesstrade。
期限はミリ秒付きUTC ISO形式。1社1リンク。キーや管理画面パスワードは入力しない。

VCは `ck.jp.ap.valuecommerce.com/servlet/referral` のsid/pid付きHTTPSリンク、
ATは `h.accesstrade.net/sp/cc` のrk付きHTTPSリンクのみ受け付ける。
ホスト形式の検証は提携確認や証券会社との対応確認を代替しない。管理画面で当該サイト・
口座案件への対応、許可された掲載表現・素材・計測要件を確認してから設定する。
今回扱わない形式や追加の広告計測タグが必要な案件は、その案件向けの対応が必要。
期限切れはAPIと画面で公式リンクへ戻す。広告リンクにはsponsoredを付ける。
比較計算は広告の有無・報酬額に依存しない。

## 残作業

### 広告素材の表示（2026-10-27更新）

承認済みのテキスト広告を使う場合、既存の5項目に `creative` を追加する。
`creative.text` は提供された広告文言をそのまま設定し、計測画像がある素材では
`creative.impressionUrl` にそのHTTPS URLを設定する。元のタグが1×1の計測画像である素材のみ対応し、バナー画像をここへ設定してはならない。画像タグのない素材だけ `null` にする。
VCでは計測画像が必須。ATではクリックURLと画像URLの `rk` が一致することを検証する。
任意HTML・スクリプト・バナー広告はこの表示形式の対象外。

URLだけの設定は公式サイトへの案内に戻す。画面は広告文言を変更せず表示し、計測画像を1×1で描画する。
広告表記はリンクの外側に表示する。実際の素材がこの形式で掲載できることと、案件ごとの掲載条件は別途確認する。
計測画像だけは最適化せず `<img>` で描画するため、専用コンポーネントに限定したESLint例外を設けた。

ローカルAPI起動はビルド先のbackendに元のworkspace依存を参照するリンクを作成する。
`pnpm --filter @app/api dev` で使用し、新しい外部依存は追加していない。
`.env` を明示的に読み込む場合は、ビルド後にリポジトリルートで
`mise exec -- node --env-file=.env tooling/run-local-api.mjs` を実行する。

公式資料の更新・承認・保存経路、ASP会員仕様と実案件での接続確認、対応カード・手数料コース・
米国株・銀行連携・サポート項目の拡充、実付与の端数処理と年会費の取扱い、
案件ごとの広告掲載確認、本番配置。既存AWSはこのコードの再デプロイまで旧版のまま。
