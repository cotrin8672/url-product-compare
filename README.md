# url-product-compare

公開構成はCloudflare Pagesの静的画面＋AWS Lambda/DynamoDBです。[Pagesの設定・公開手順](docs/cloudflare-pages.md)を参照してください。Pages用ビルドは `rtk proxy mise exec -- pnpm run build:pages`（`PUBLIC_API_BASE` が必要）です。AWSスタックは配置済みですが、Pagesの作成・公開URLに合わせた接続許可の更新と、最新コードの反映は別途必要です。

既存のSolid/TypeScript製商品比較UIを維持しています。従来のXserver用成果物も `rtk mise run xserver:static` で生成できます（`SITE_ORIGIN`・`PUBLIC_API_BASE` が必要）。[静的ホスティング手順](docs/xserver-static-site.md)を参照してください。

Xserver＋Lambda向けの実装・配置手順は [移行手順](infrastructure/lambda/README.md) を参照してください。画面はXserverの静的配信、API・比較ワーカー・期限切れ整理はLambda、比較ジョブ・カテゴリ定義・共有リクエスト制限はDynamoDBです。新しい実行経路にPHP・Firebase・Render・SQSは不要です。実サーバーでの疎通・公開前確認は同手順に従って行ってください。

アフィリエイトの採用先・登録手順・規約の調査結果は [調査メモ](docs/affiliate-research.md)、商品3サイト・返礼品2サイトの取得APIと返礼品の項目抽出・横断比較は [API仕様と設定](docs/commerce-api.md) を参照してください。新しいAPIは既存の比較画面・採点にまだ接続していません。

外部APIの通信は [楽天](packages/rakuten-api/README.md)・[バリューコマース（さとふる／Yahoo）](packages/valuecommerce-api/README.md)・[Jev](packages/jev-api/README.md) の独立したpnpm workspaceライブラリで提供します。各パッケージはbackendに依存せず、JavaScript・型宣言をビルドして他プロジェクトでも利用できます。比較ロジックと評価基準はbackend側です。

商品URLから、入力商品と候補の価格・仕様を比較するサービスです。現在の通販APIは楽天です。ノートPC・デスクトップPC・タブレット・スマートフォン・テレビ・モニターには専用の抽出・採点ルールを用意し、それ以外は楽天ジャンルの属性一覧とJevで比較項目を自動選定します。通販APIは登録したプロバイダへ委譲します。

全カテゴリで新品と確認できる掲載のみを比較対象にします。中古・再生品・商品状態が未確認の掲載は受け付けません。検証済みの成果リンクも必要です。容量・重さ・画面サイズなどの条件判定、価格順位、単位換算、総合点の集計はプログラムが処理します。項目別・総合とも100点満点の比較指数です。既存6カテゴリは確認済み数値の相対比較を維持し、CPUの型番から総合性能を推測しません。自動カテゴリでは確認済み属性値をJevで採点します。条件を満たす安価な商品も候補に含めます。

メイン経路 `POST /api/comparisons` は非同期ジョブを開始し、進捗・取消・期限内の結果復元を提供します。同期の `POST /api/compare` も互換用に保持します。いずれも **OpenAIを呼びません**。楽天APIの明示された仕様を先に抽出し、判断が必要な値は任意設定のJevへChoiceで送ります。商品名・本文中にある値と引用だけを選ばせ、未知・矛盾・低確信・失敗は未確認のまま表示します。自動カテゴリの確認済み値は最後にScoreでまとめて採点します。Jev未設定でも価格・明示仕様を比較できます。

## 起動

Windowsでは `C:\Users\gummy\.codex\RTK.md` に従い、シェルコマンドに `rtk` を付けます。Node.js/pnpmはmiseの固定版を使います。

```sh
rtk mise trust
rtk mise install
rtk mise run install
rtk mise run verify
```

Git対象外の `.env` に、`.env.example` の楽天設定6項目を設定します。楽天キーとJevキーはサーバーだけに置きます。`RAKUTEN_DATA_AUTHORIZED_UNTIL` は取得・表示・成果リンク・AI送信条件を再確認する内部停止期限です。

```powershell
rtk mise run firebase:package
rtk mise exec -- node --env-file=.env apps/api/dist/firebase/apps/api/src/local.js
```

別のターミナルで画面を起動します。

```powershell
rtk mise exec -- pnpm --filter @app/web dev --host 127.0.0.1
```

`http://127.0.0.1:5173/` を開き、楽天の商品URLを入力して比較します。カテゴリは自動判定し、曖昧な場合だけ利用者が選択します。ブラウザーにトークンや楽天キーを入力する必要はありません。APIサーバーの公開入口が比較用の経路だけにサーバー内の認証を渡します。ローカルでは画面のオリジンを `http://127.0.0.1:5173` に限定します。配置先が異なる場合はサーバーの `API_ALLOWED_ORIGIN` を指定します。

Jevの比較項目選定・抽出補助・採点には `JEV_API_KEY`（または既存の `TYPESAFE_API_KEY`）と `JEV_MODEL=jev-1.13.0` を設定します。キーを設定しなくても価格・明示仕様の比較は動作しますが、未登録カテゴリの主要項目は選定しません。旧診断経路向けの `OPENAI_API_KEY` はメイン画面に不要です。

## 比較の挙動

未登録カテゴリは、楽天ジャンルAPIの属性名から重複・管理用・販促項目を除き、JevのYes/No判定（Noul、yes確率0.7以上）で主要項目を最大16個選びます。選定はジャンルごとに1回のAPI呼び出しで、成功結果は24時間、選定失敗は5分キャッシュします。LambdaではDynamoDBで定義と選定用リースを共有し、再起動・別インスタンスでも期限内は再利用します。モデル・選定ルールの版・AI利用可否をキーに含め、許可の失効も再確認します。DB障害時は有料APIへの再選定に迂回しません。ローカルの既定構成は最大128ジャンルのメモリキャッシュです。属性一覧がない場合も価格比較を受け付けます。

値は商品名・商品説明のラベル付き記述・HTML表・短い `【項目名】値` の節から取得します。属性名との表記が違う場合は、数量・短い文章などの引用候補を最大128個取り出し、項目ごとに最大8候補をJevへ渡します。単品重量と総重量、個数、付属品・増設上限・バリエーションを区別して選ばせます。自動カテゴリは入力商品と最大5候補・主要16項目で最大96問、16問ずつ最大6回のChoiceです。既存6カテゴリは最大24問・1回を維持します。候補数の上限や掲載に記載がない場合は取得できず、未知・低確信・矛盾を埋めません。主要項目と取得値は初めから展開します。

自動カテゴリの採点は、2商品以上で引用付きの値を確認できる項目だけをJevのScoreへ1回まとめて送ります。同じ項目の同じ値は1問を共有します。5段階の期待値（0〜4）を0〜100点へ換算し、信頼度0.6未満は採用しません。好み・産地・量の違いだけで優劣を付けず、確認できる機能上の差を評価させます。点数は商品の品質を保証する確率ではありません。ジャンル選定を含むJev呼び出しは初回最大8回、定義キャッシュ済みなら最大7回です。

自動カテゴリも新品限定です。「新品」の根拠がない食品などは商品状態が未確認となり、比較対象外です。ふるさと納税表記のある掲載は同じ表記の候補に限定し、通常販売品と混ぜません。自治体・控除上限・申込条件などの寄付固有の比較はまだ行いません。

評価の内訳は採点できた項目をカタログ順に最大6項目まで通常表示します。「詳細項目を表示」で、残りの評価軸とCPU・GPU型番、OS、通信規格などの仕様を全商品まとめて開閉します。全商品で未確認の項目は省略し、一部の商品で未確認の値は「—」で表示します。0や「なし」は確認済みの値として残します。数値が取得できても採点できない項目は仕様欄に表示します。総合点が全商品で未確認の場合は総合評価行を省略し、開閉で総合点・順位は変えません。PCのコア数・GPUメモリ・端子数などは数量の相対評価で、CPU/GPUのベンチマーク性能点ではありません。

- 入力URLと掲載URLの完全一致を確認します。数値のURL末尾は商品コード検索の候補に使い、別URLの商品なら採用しません。続いてURL末尾・補助の商品名・カテゴリ語によるショップ内検索を最大3回行います。商品を見つけられない場合だけ商品名欄を出し、URLを保持したまま再試行できます。
- カテゴリ語と楽天ジャンルで最大3ページ、各30掲載を取得し、新品と確認できる各ページ最大6掲載を比較処理へ渡します。比較処理の対象は入力商品と別に最大18掲載、応答は入力商品と最大5候補です。新品が見つからないページでも、後続ページがあれば探索を続けます。
- 型番と有効なJANを製品APIで照合し、同定済みJANの重複を整理します。入力商品が条件外でも表示します。
- 仕様の欠損、矛盾、選択式バリエーション、増設上限を標準仕様として埋めません。出典APIの区分と引用は内部データとAPI応答に保持します。
- 価格順位は、表示対象の必須条件が確認でき、適合商品の正の税込掲載価格が単一値の場合に限ります。同額は同順位です。送料・ポイント・クーポンは順位に含みません。
- 確認済みの数値が2商品以上ある項目を、最良値＝100で相対換算します。端子数などカタログで0を許可した項目は、明記された0も採点します。JAN未同定でも掲載に明記された仕様は採点します。欠損を0で補完せず、他商品の既知の点数を消しません。価格・重さは小さい方、容量・画面サイズ・解像度・更新回数は大きい方を基準にします。
- 総合は共通項目の重み付き平均で、価格以外の共通項目が必要です。既存6カテゴリは適合商品すべてで確認できる共通項目を均等に集計します。自動カテゴリは、入力商品で採点できる仕様項目を優先し、同じ項目で採点できる商品数が最も多い組を選び、その組全体の共通項目を均等に集計します。採点対象の項目名と商品数を画面に表示し、対象外の商品の総合点は未確認のまま残します。全適合商品で総合点が揃うまでおすすめ順位を保留し、同点は同順位にします。おすすめ候補は入力商品の既知の仕様項目が揃う掲載を優先して補充します。
- 探索範囲、除外・保留・重複件数と打ち切り理由はAPI応答に保持します。順位は取得した商品の比較で、全市場の最安を意味しません。
- 商品URLの変更時に旧結果を消し、取得情報と広告リンクの期限が切れたら再取得を案内します。

不正URL・危険なスキーム・バリエーション指定は送信前に拒否します。通常の楽天URLと、商品への遷移先を明示した楽天成果リンクを受け付け、追跡情報を正規化します。通信失敗は入力を残し、壊れたJSONやHTML応答も短いエラーから再試行できます。商品・属性はHTMLとして描画せず、リンク・画像とAPI応答の形式・サイズを検証します。本番配信のCSP、HTTP入力制限、受信中の応答サイズ制限を追加しました。詳細は[URL復帰とセキュリティの確認](docs/security-and-recovery-review-20261013.md)に記録しています。

ローカルのジョブはメモリで実行します。FirebaseではFirestoreのジョブ作成トリガーで実行し、操作キー・入力ハッシュ・リビジョンで再送と取消の競合を制御します。結果の保存・復元はプロバイダの保存許諾がある場合だけ有効です。楽天設定の任意の `resultStorageAuthorizedUntil` は、実際に得た保存許諾の期限を指定する欄です。未設定では商品結果の永続保存を拒否します。結果の期限は最大15分と掲載・許諾期限のうち最も早い時刻です。

共有キャッシュ、匿名認証・App Check、収益計測、WordPress移行は追加していません。公開入口は1インスタンスにつき接続元アドレスごとに有料処理を伴うPOSTを毎分6回まで受け付けます。これは共有された利用者別上限ではありません。操作ごとのアクセス鍵で結果を保護し、旧診断用のBearer認証は維持します。

## 検証と資料

`rtk mise run verify` が整形、型情報付きESLint、TypeScript、Knip、guardrail、機能テストを実行します。既存6カテゴリに加え、自動カテゴリ、キャッシュ・同時選定・期限・取消、6商品のバッチ抽出、丸められた確率・不正な回答・部分失敗、100点換算・同一値の共有・共通採点項目、外部応答・出典・価格順位・ジョブ復元をモックで確認します。通常の検査で外部の課金APIを呼びません。

2026年10月10日に実APIとブラウザーで [UCC カップコーヒー](https://item.rakuten.co.jp/rakuten24/4901201157554/) を確認しました。未登録のインスタントコーヒーで主要6項目を自動選定し、入力商品と5候補を表示しました。以前は全36セルが未確認でしたが、修正後は全6商品から合計9セル（単品重量2g、総重量200g×5袋、個装入数50本、原材料コーヒー豆など）を取得しました。価格・原材料が共通する3商品は総合76・36・32点を表示し、残る3商品は総合点と全体順位を保留しました。再実行では10セル・総合77・36・33点となり、再推論時の抽出・採点には揺れがあります。掲載に記載がない属性は引き続き未確認です。同じジャンルの再検出では項目選定のJev呼び出しは0回でした。

最初の修正後実行は項目選定1回・抽出3回・採点1回で、Jev入力トークンの合計は52,052でした。[公式モデル料金](https://docs.typesafe.ai/models)の入力100万トークンあたり$0.042・出力無料で計算すると約$0.0022です。1例の実測であり、項目数・候補文・再試行・インスタンスごとのキャッシュ状態により変わります。[ふるさと納税の米](https://item.rakuten.co.jp/f012246-chitose/ci290sku/) は以前の検証ではショップ内検索の上限で元商品を特定できませんでした。

広い実商品群での仕様充足率、Jevの抽出精度、バリエーション一致、成果反映、収益はまだ実測していません。Jev使用時にはAPI費用、その他の処理には基盤費用が発生し得ます。

## 構成の保護

TypeScriptはESM・named export・`type`・分離した`import type`を使います。WebはAPIクライアントだけでデータを取得し、API/workerはbackendへ委譲します。比較ロジックはDB・キュー・フレームワークに依存しません。外部の`unknown`は境界で検証します。

依存・lockfile・Lint/formatter/TypeScript/Knip設定・除外・生成タスク・CI・guardrail・CODEOWNERSの変更には人のレビューが必要です。今回の公開ページ生成とFirestoreジョブのTTL設定もレビュー対象です。検査を弱めず、リモート保護設定やマージを自動変更しません。
